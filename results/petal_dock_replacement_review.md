# PetalDock100 V2 替换候选评估

可以作为新的接口实验场景接入。当前 MuJoCo/Pinocchio 的机械臂加载、挂载和动力学
兼容性已核对；尚未证明它在本项目的完整机械臂插入轨迹下通过验收。当前默认接口
与所有旧实验资产保持原样。

本次只把附件解压到临时目录并评估。附件 README 中的演示、重建和安装命令作为
资料读取，没有将它们视作用户要求改变当前项目的指令。

## 独立核对

- MuJoCo 3.12.0 可加载成对场景；441 个碰撞网格均能构成非退化凸包，所有导出
  顶点均为凸包顶点。每侧含 416 导向块、24 止挡块、1 底板代理，无需再次 CoACD。
- 在本项目的 iiwa14_arm.xml 挂载成功，仍为 7 个关节自由度；增加质量
  0.391690843 kg。工具原点与 attachment_site 的位置/旋转误差为零，法兰 F/T
  传感器可加载。
- 直接用 Pinocchio 读取带 include 的挂载 MJCF 时出现 `unordered_map::at`。
  使用 MuJoCo 展开 MJCF 后 Pinocchio 可读取，工具 frame 可用。两个关节配置下
  新工具 FK 与 MuJoCo 差异约 1e-14，关节质量矩阵最大差异约 2.9e-14。
- 名义姿态与后撤 25 mm 的状态无穿透；过插 1 mm 检出约 1 mm 最大接触穿透。
  错开 45° 的探针检出碰撞，最大接触深度约 0.615 mm；附件 MuJoCo 3.14.0 的
  记录为约 4.294 mm，因此该包错误角度检查的 `>1 mm` 断言在当前环境不成立。
  这些是逐凸体碰撞器的距离，不能直接等同于整件实体的几何穿透深度。
- 附件 SHA256SUMS 有 203 条，其中 194 条与当前包内文件不符；它不是这版模型的
  有效资产清单。接入时应重新生成清单并标记版本。

独立结果位于 `runs/petal_model_review_20261002/`，其中保存附件整体指纹和实际
检查范围。本次未重新生成 CAD、未更改项目依赖、未切换默认模型。

## 需要的适配

1. **位姿与接口封装**：新的 body 原点是法兰安装面，+Z 指向对接面。
   名义相对姿态是 `Rz(45°) Rx(180°)`、法兰间距 46.4 mm；mating site 位于
   z=23.2 mm。封装为本项目的 dock/sensor_site 片段，重新定义规划和验收 frame。
   旧接口的内部 40° 相位、15 mm 挂载偏移和旧 cylinder_link 定义不可照搬。
2. **动力学一致**：同步更新 MuJoCo 与 Pinocchio 的质量、质心和完整惯量张量，
   不重复保留旧 URDF 里 1 kg、对角惯量 0.1 的固定工具。可采用已验证的展开
   MJCF 路线，也可提供新的 URDF。控制增益需按新的完整模型重新验证。
3. **独立就位评估**：当前 InterfaceGeometry 固定读取单个 dock_geom，针对旧冠形
   接口搜索相位。新接口由多个视觉网格与止挡组成，需要独立的位姿/止挡接触定义，
   继续保留估计与真值分离，控制器只读取目标估计。
4. **控制与碰撞验证**：先在关闭 weld 时跑本项目同一组 nominal/XY/XY+yaw 和
   高低绕轴刚度对照，逐步记录净载荷、逐接触载荷、惯性和平衡残差。包内用
   0.5 ms 步长、摩擦 0.15、solref 0.003；不得自动覆盖旧场景后宣称同条件改善。
   441 块比前一候选的 130 块更多，接触数和步长/离散度收敛仍需验证。
5. **锁定独立建模**：附件 weld 是就位后启用的抽象约束，不是锁销/凸轮的真实
   力学；导向、落座与锁定应分别验收。包内 15 组无 weld/无横向姿态定位刚度的
   数据可作为候选证据，但属于自由刚体测试台，不是本项目机械臂控制的验证结果。

建议保留旧场景用于回归，增加一个 PetalDock 场景作为新的主接口候选，通过上述
完整动力学验收后再决定是否替换默认。

附件动态演示 `demo.py` 的复跑被自动审批拒绝，理由是当前请求授权模型评估，
未明确授权执行附件脚本；可能存在任意代码和本地副作用。等待明确授权前，未通过
其他途径执行该脚本或导入它来进行动态演示。

MuJoCo 的 weld 会约束两物体全部相对自由度，见
[官方文档](https://mujoco.readthedocs.io/en/latest/XMLreference.html#equality-weld)。
