# 默认 HexFrame 模块组装结果

用户提供的 Astra HexFrame 已成为本独立实验默认模块。原资源保存在 `../../assets/hexframe_module/`，包括 MIT 许可、参数化 CAD、STEP、GLB、完整 MJCF 和原预览。原资源文件未改写；场景适配由 `../../hexframe_integration.py` 完成。

相比旧模块，优势是：梁与安装板的连接关系更清楚，框架有支撑杆和安装孔细节，提供参数化 CAD，以及按 CAD 体积估算的质量惯量和分开的碰撞模型。这些优势不代表通过了结构强度或制造校核。

默认使用原尺寸约 341 × 344 × 170 mm、估算质量 3.508 kg；没有缩放外观或沿用旧质量。资源端口 3/0 映射为场景接口 1/4，保持“机械臂接接口 1，接口 4 向下对接模块 2 接口 1”。根间距 46.4 mm，模块中心距约 323.528 mm。新模块更大，作业位置调整为 X=±0.34 m、Y=0.35 m、Z=0.195 m，抬升高度 0.78 m，撤离 75 mm，仍采用左侧组装/中央机械臂/右侧存储布局。

## 验证结果

| 项目 | 结果 |
|---|---|
| 本机资源几何验证 | MuJoCo 3.12.0 下通过；端口位置、旋转、中心开口、分离/过插检查通过 |
| 新默认接入测试 | 7 项通过；米制尺寸、CAD 惯量、六侧面映射、名义对接与止挡过插、全程轨迹可达性、基座接口配合、存储/备用接口配合与安全解锁、异常后的配置恢复 |
| 全流程 | PASS，53 s，四次锁定交接顺序正确 |
| 首次接触 / 锁定 / 释放 | 35.112 / 36.857 / 47.600 s |
| 峰值轴向接触力 | 1.855 N |
| 最大求解穿透 | 0.00223 mm |
| 释放时抓取约束合力 | 0.01603 N |
| 终态模块位置误差 | 0.00036 mm，理想锁定仿真结果 |
| 存储接口峰值接触力 | 0.00190 N；与模块间接触载荷分开记录 |
| 异常 | 未检测到已配置结构碰撞、关节越限、力矩饱和或仿真警告 |

就位门限保持原位置、姿态、速度和载荷要求，并新增真实止挡接触承载条件；全部连续满足 0.5 s 才锁定。最初 14 s 接触阶段未达到持续止挡条件，因此拒绝锁定；改为允许更长的接触阶段后通过，没有降低锁定门限。53 s 为这一完整流程的时长，不是最优时间。

标准存储端口接入后的首次 0.3 N 接触目标运行出现间歇失载，连续就位最长 0.432 s，正确拒绝锁定。诊断数据保存在 `attempt_0p3N_storage_socket/`，未保存完整源码快照。新默认接触目标改为 0.4 N 以改善持续承载；0.15–0.6 N 就位载荷范围、0.5 s 连续时间，以及位置、姿态、速度、穿透和止挡门限均未放宽。

活跃组装面以及存储、备用接口采用原资源精细导向/止挡凸碰撞；其余模块头部使用包络代理，框架是独立盒形梁碰撞。机械臂对接头也换成匹配的 PetalDock 外观，其捕获与锁紧仍采用理想 weld。存储接口的接触单独记录，不混入模块间接触力。新接口单个名义带机械臂流程通过；尚未复核完整流程的误差网格、半步长、噪声或自由漂浮动力学。旧模块性能数字不适用于新资源。

`audit.json` 从记录重新核对交接顺序、卸力和锁定前连续 500 个物理样本，并核对来源摘要。锁定边界样本保存接受锚点修改之前的物理误差；逐步日志另外保存止挡承载和全部就位条件的布尔量，审计要求整个窗口持续满足。该审计核对保存的观测，不重新运行接触求解器。

## 基座连接与视频

`base_connection.png` 为基座标准接口与模块 2 接口 4 的局部特写，由 `render_hexframe.py` 生成。

`storage_connection.png` 展示初始存储锁定与空闲备用接口，`storage_released.png` 展示模块提起后的空闲接口。

模块 1 初始通过朝下的侧面接口 4 锁在朝上的 **PetalDock100 V2 存储接口**；备用位为同款空闲接口，两位间距 0.40 m。原叉形存储托架已移除，三处台面接口统一为低矮圆形安装座和同款对接头。

`storage_lock` 理想 weld 作用在存储端口与模块 1 接口 4 的配合面。模块 1 保留自由关节；机械臂与其接口 1 锁定确认后，才解除存储锁并竖直提起。未抓取就解锁会被拒绝。`storage_trace.npz` 保存每步存储接触力、穿透、配合面分离和三处锁定状态，审计要求交接时始终有支撑、先抓取再解锁，以及抬升完成后持续脱离存储接口。备用位本轮保持空闲，未执行回存动作。

模块 2 的组装定位托架已替换为低矮安装座和匹配的 **PetalDock100 V2 基座接口**，连接模块 2 朝下的侧面接口 4；其朝上的侧面接口 1 接收模块 1 接口 4。

基座接口采用与机械臂端部相同的接口网格；基座与模块 2 接口根间距为 46.4 mm，法线相向、配合相位为 45°，两侧 mating site 重合。模块 2 挂在基座接口的固定父子刚体变换下，表示初始已锁定，没有自由关节。没有模拟基座接口的捕获、解锁和锁销动力学；模块间插合仍采用导向/止挡接触和持续就位后理想锁定。`geometry_check.json` 和 `audit.json` 记录新的基座配合验证。

模块名称放在画面顶部说明栏；特写标题放在特写画面外，避免文字遮住接口。视频从 1 ms 步长的 MuJoCo 动力学结果生成：`rollout.npz` 以 100 Hz 保存状态，渲染器按 24 fps 选取已记录状态，分别渲染作业区与接口特写，再叠加字幕，使用 FFmpeg/libx264 编码为 1280 × 720 MP4。视频是仿真状态回放，不是生成式视频；回放不重新积分动力学。

## 使用

从项目根目录运行：

```bash
# 默认模块，完整仿真和视频
OPENBLAS_NUM_THREADS=1 .venv/bin/python experiments/orbital_showcase/crown_assembly.py --video

# 回放，不重新计算
.venv/bin/python experiments/orbital_showcase/render_hexframe.py --video

# 旧模块
OPENBLAS_NUM_THREADS=1 .venv/bin/python experiments/orbital_showcase/crown_assembly.py --module legacy --video
```

`preview.png` 为全景与初末状态，`assembly_sequence.mp4` 为 53 s 视频；`resource_geometry_validation.json` 是本机原资源几何检查，`geometry_check.json` 是场景映射检查，`validation.json` 与 `audit.json` 为本轮验证。源码、资产与模型摘要见 `source_manifest.json`，压缩包来源见原资源目录 `IMPORT.json`。
