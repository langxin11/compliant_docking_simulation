# 代码与注释规范

本规范适用于项目自有维护代码，以控制模块中已有的物理约定说明为参照。
目标是让中文用户不必先翻译英文或猜测术语，就能理解代码的用途、选择理由与物理含义。
短工具不需要复制控制器的长篇数学推导。
根目录 `AGENTS.md` 将这些要求纳入代理工作流程，人工贡献同样遵守。

## 模块与接口

- 模块开头说明职责、输入输出及重要边界；实验入口还说明唯一主要变量、输出位置和评价含义。
- 模块说明、函数说明及关键逻辑注释以中文为主；代码标识符、文献名和 Google 风格字段名保留英文。
- 术语首次出现给出中文含义，例如 body（末端自身坐标系）、wrench（力与力矩的六维向量）、rollout（单次仿真记录）。后续可用短术语，不堆叠缩写。
- 本次修改涉及的英文说明同步补齐中文；不强制每句中英重复，也不改写冻结快照。
- 公共函数与类至少一句行为说明；参数语义不显然时使用 Google 风格 `Args`、`Returns`、`Raises`。
- 写文件、改状态、持有可变数组、返回视图或可能拒绝复用等副作用应明确写出。
- 私有的简单转发可用简短说明；涉及数学、接触、时间或复现约束的辅助函数仍需解释约定。

## 物理代码必须交代的约定

| 类型 | 需要说明 |
|---|---|
| 位姿、速度、力矩 | 单位、形状、世界/body/sensor 坐标、力矩参考点 |
| 六维向量 | 线量/角量顺序，例如 `[v; ω]` 和 `[f; n]` |
| 采样与控制 | 物理步长、控制周期、反馈年龄、积分前/后采样及保持方式 |
| 控制矩阵 | A/D/K 的含义、坐标系、维度、零刚度方向与正定等条件 |
| 实验误差 | 输入是 m 还是 mm、角度是 rad 还是 deg、误差加在估计还是真值 |
| 评价 | 时间窗口、阈值单位、候选落座/完整系统/锁紧的区别 |

例如单位转换接口应写清：

```python
def error_tuple(point):
    """将网格误差转换为单次试验输入，偏航继续使用角度。

    Args:
        point: (dx_mm, dy_mm, yaw_deg)，施加到规划目标估计的误差。

    Returns:
        (dx_m, dy_m, yaw_deg)；不修改输入。
    """
    return point[0] / 1000., point[1] / 1000., point[2]
```

注释解释“为何如此”：例如反馈移矩保证 wrench 与 Jacobian 同原点，或固定控制周期以隔离物理步长因素。
避免“遍历列表”“返回结果”一类重复代码的注释。引用方程时说明实际实现范围与偏离，不能把未实现能力写进说明。

## 维护方式

先更新本次改动涉及的接口说明，再处理独立的整批规范化任务。
不修改第三方导入、`results/` 冻结证据及 `source_snapshot/` 来统一语言。
迁移锚点中的函数若要求 AST 原样保留，可先用邻近注释补充契约。

注释修订应与行为修改清楚区分。去除 docstring 后 AST 相等只能证明没有语法层面的执行逻辑变更，
不表示源码指纹或 CLI 帮助文字不变；历史运行仍按原来源解释。
