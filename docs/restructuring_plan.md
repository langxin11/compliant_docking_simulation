# 三层项目重构计划

状态：计划草案，尚未实施。日期：2026-10-04。

本计划依据已确认的三个层次组织项目：**模型与接口 → 柔顺控制算法研究 → 完整对接/装配**。
完整对接/装配承担系统级验证和 Demo 展示。模型与接口提供明确的研究条件；
柔顺控制算法研究通过受控实验建立结论。

## 1. 重构目标与约束

重构完成后，读者应能从首页直接回答：

1. 实验使用什么模型和接口，作了哪些假设？
2. 算法研究回答什么问题，每项对照只改变什么？
3. 完整系统集成了哪些已验证能力，任务完成的依据是什么？

本次重构首先整理职责、入口、实验协议和证据归属。算法改进、接口设计变更、
新增物理机制分别立项；涉及行为变化时使用新配置、新实验和新结果目录。

实施约束：

- 保留旧命令兼容入口、已归档结果、源码快照、资产来源与哈希记录。
- 结构迁移期间保持控制公式、增益、几何、物理参数和验收阈值不变。
- 不将历史失败改写为成功，不用系统 Demo 为算法优越性提供证据。
- 原始导入资产保留唯一来源，避免目录整理产生多份不同步的模型。
- 工作区已有 `experiments/se3_free_space_plots.py`、`demo/se3_free_space_validation.png`
  的改动和未跟踪的 `report/` 内容先行核对，迁移时保留。

## 2. 三个层次的职责与交付

| 层次 | 核心职责 | 可变化的内容 | 向下一层交付 |
|---|---|---|---|
| 模型与接口 | 定义研究对象、检查模型一致性、给出接触与坐标约定 | 在独立模型验证或接口设计实验中改变几何、离散精度等 | 固定版本的资产、参数、坐标/配合定义、适用范围与验证记录 |
| 柔顺控制算法研究 | 在固定研究对象上隔离变量，分析控制行为和适用范围 | 每个研究问题预先声明的控制因素；另设误差与数值复核实验 | 可复现的控制配置、实验矩阵、评价标准、结论和失败边界 |
| 完整对接/装配 | 集成规划、控制、状态切换与执行流程；完成系统验证与展示 | 在独立系统验证中改变任务扰动或检测策略 | 全流程验收记录、故障记录、状态回放与 Demo 视频 |

依赖规则：算法实现不依赖具体 Demo 的阶段和布局；系统编排调用明确的控制接口；
模型与接口通过版本和配置被引用。绘图、遥测、数据审计属于共享支撑能力，
不另设为研究主线。

### 2.1 模型与接口：先明确假设，形成稳定实验对象

主研究的初始范围建议如下，实施时写入基线说明：

- 固定基座、固定目标、零重力；刚性机械臂和接口。
- 机械臂、工具的质量惯量、安装变换和关节限制已给定，并经过一致性检查。
- 每项算法对照固定接口版本、碰撞表示、摩擦、接触求解设置和配合定义。
- 主研究先覆盖 XY 与绕插入轴偏航估计误差；倾斜误差、重力工况和浮动基座分别扩展。
- 规划与控制仅使用声明的估计量和反馈；真实目标与接触标签仅用于评价。
- 单接口研究以稳定落座为任务终点；真实锁紧、制造公差和结构弹性另设验证。

基线选择建议：先以已有原版 PetalDock100 控制对照所用资产作为算法研究基线，
保持历史证据可比。`angle1_blend030` 保留为接口层候选，沿用现有未晋升结论。
其数值复核和选型可以独立推进，避免成为所有控制实验的前置任务。

每个基线需要一份简洁记录：资产版本/哈希、场景、坐标系与单位、配合位姿、
质量惯量来源、接触参数、适用假设、检查结果，以及已知限制。
模型检查通过仅证明它满足声明的仿真用途，不能替代实物标定。

### 2.2 柔顺控制算法研究：围绕问题组织实验

建议将当前核心问题收敛为以下两项；已有三控制器实现作为方法库和已有对照保留。

| 编号 | 研究问题 | 对照设计 | 固定因素 |
|---|---|---|---|
| RQ1 | 接触后的绕轴释放，对相位纠偏和稳定落座有什么作用？ | 固定高刚度、固定低刚度、接触后绕轴释放 | 接口、横向策略、惯量/阻尼、轨迹、初值、估计误差与评价条件 |
| RQ2 | 在绕轴策略固定后，横向释放能否减弱错误目标回拉、改善落座？ | 保持 XY 刚度与接触后释放 XY 的同点配对 | 接口、绕轴策略、轴向推进、惯量/阻尼、轨迹与评价条件 |

对于每项问题，先写研究协议，再运行新增实验：

1. 假设、待验证机制、唯一的主要变化因素。
2. 同点配对的工况、固定配置、允许误差和执行预算。
3. 落座、残差、稳定时间、真实接触载荷、关节安全等评价指标。
4. 失败定义、完整数据记录和结论可以推广到的范围。

误差网格用于检验策略的适用范围；数值复核用于检验结论的可信度。
改变物理步长时固定控制周期和反馈延迟；改变控制周期应作为另一项实验。
接口参数消融、减速、预紧和搜索策略分别设计对照，避免一次同时修改多个因素。

研究报告需要区分：已实现的方法、已复现的结果、项目新增的实验发现。
各轮使用不同工况集合时，不将通过数量串成统一的成功率提升曲线。

### 2.3 完整对接/装配：系统验证与 Demo

系统流程为：预检 → 接近/抓取 → 转运 → 接触对接 → 持续就位 → 交接/卸力 → 撤离。
单接口完整对接按其实际任务使用对应阶段；HexFrame 展示更完整的装配流程。

系统验收检查流程完成、状态切换顺序、载荷与关节约束、支撑/交接关系、
释放前卸力和撤离距离。Demo 从验收运行保存的状态生成，关联同一运行记录。
预检、完整验收、回放分别标识，视频生成成功不能自动代表验收通过。

**现有集成差距**：HexFrame 当前使用独立的 `assembly_admittance` 流程，
包含 MuJoCo 偏置补偿关节伺服与接触导纳；尚未集成单接口研究的 SE(3) 阻抗控制链路。
因此，现有 HexFrame 结果只能证明其当前系统配置的流程可用性。

本次结构重构应显式记录这一差距。后续若将研究策略接入 HexFrame，作为独立集成工作：
明确末端控制点、负载切换、反馈来源、控制周期和抓取约束；先完成局部回归，再执行全流程验收。
原导纳流程保留为系统基线，新集成的结果独立归档。

## 3. 目录与入口方案

按职责建立三个对外实验目录，共享实现保持单一来源：

```text
experiments/
  models_interfaces/     # 模型检查、接口几何验证与独立设计对照
  control/               # 自由空间验证、RQ1/RQ2、误差范围与数值复核
  system/                # 完整对接/装配预检、验收、回放与 Demo
  ...                    # 迁移期保留的旧命令兼容入口

src/compliant_docking/
  control/               # 控制算法及接触策略
  planning/              # 运动参考与运动学
  simulation/            # 物理环境及一致性检查
  assembly/              # 装配状态、交接与系统编排
  models.py, scene.py    # 当前模型加载与场景装配公共能力
  ...                    # 共享遥测、评价、坐标变换与渲染

docs/
  research_scope.md      # 三层总览、研究假设、证据使用规则
  models_interfaces.md   # 模型/接口基线与资格检查
  control_research.md    # 研究问题、对照矩阵与结论
  system_validation.md   # 集成状态、系统验收与 Demo
  development_plan.md    # 当前完善任务与状态
```

实施顺序是先梳理依赖，再迁移实验编排和建立兼容入口。避免仅添加三套名称不同、
仍可任意切换研究目的的包装器。新控制入口不提供接口调形模式；系统验收入口
不允许用临时更换控制器或缩短时长冒充原系统验收。

不强行将所有运行库搬成三个大包：现有 `control/` 和 `assembly/` 已有明确职责，
底层数学、模型加载与物理引擎按可复用的软件职责组织即可。
资产和历史结果的物理搬迁要以依赖与来源检查为前提。

### 现有实验的归属

| 当前入口或内容 | 目标归属 | 证据用途 |
|---|---|---|
| `prepare_petal_*`、`petal_designer.py`、几何对照与候选复核 | 模型与接口 | 模型生成、独立接口选型与资格检查 |
| `se3_free_space.py`、控制器数学验证 | 柔顺控制算法研究 | 控制行为与实现正确性 |
| `petal_insertion_suite.py` 中绕轴、横向和误差网格模式 | 柔顺控制算法研究 | 固定接口上的控制对照与适用范围 |
| `compare_frameworks.py` | 柔顺控制算法研究中的历史对照 | 在原协议范围内保留结论 |
| `assembly/`、HexFrame 正式入口、回放 | 完整对接/装配 | 系统级验收与 Demo |
| `hexframe_validation/` 的 P0/P1/P2 | 完整对接/装配的扩展验证 | 系统数值复核、位置扰动、测量噪声与判定策略对照 |
| 冠形接口、凸碰撞和旧展示实验 | 按原问题分类的历史实验索引 | 保留结论和复现命令 |

P2 修改了系统判定策略，报告需独立标识该变量；其结果不能直接替代控制主线的证据。
历史报告中的接口改善、控制改善和系统通过分别引用，不合并归因。

## 4. 分阶段实施与完成标准

| 阶段 | 具体工作 | 完成标准 |
|---|---|---|
| A：建立当前基线 | 清点工作区、代码依赖、资产、入口与归档；记录已有检查结果 | 有三层归属表、依赖图和基线检查记录；已有修改得到保留 |
| B：固定研究边界 | 完成模型基线记录、RQ1/RQ2 协议、系统验收范围及集成差距说明 | 每项实验均能指出主要变量、固定条件、判据及有效范围 |
| C：整理实验入口 | 建立三个目录；分离控制/几何编排；保留旧入口兼容；调整必要导入 | 新入口职责单一；旧入口仍可用；核心库不反向依赖实验脚本 |
| D：整理系统验证与 Demo | 明确预检、完整验收、回放；分类 P0/P1/P2；关联视频与验收产物 | 系统结果标明实际策略与版本；预检/视频/验收状态可区分 |
| E：重写阅读路径 | 更新 README、MkDocs 导航、研究范围和完善路线图；核对报告叙事 | 首页按三层组织；历史记录和当前计划清楚区分；文档链接有效 |
| F：迁移验收 | 运行静态检查、文档构建、受影响测试及必要行为回归 | 新旧入口配置等价；系统正式入口和独立审计通过；变更范围可审查 |

先完成结构与证据整理，再确定新增科研实验。单接口策略迁入 HexFrame、制造设计、
重力扩展等任务放在相应后续阶段，不与目录重构同时改变物理行为。

## 5. 验证策略

- 文档调整：执行严格文档构建并核对相对链接、当前状态和历史报告引用。
- 入口迁移：验证参数、默认配置、输出位置、失败退出语义和多进程导入行为。
- 编排迁移：比较新旧入口构造的有效配置；检查资产哈希和来源快照仍完整。
- 物理行为相关迁移：运行对应的数值锚点与代表工况，比较关键事件和评价指标；
  出现漂移时先定位迁移问题，不自动重建阈值或基线。
- 系统交付：运行完整 HexFrame 流程和独立审计；使用同一运行记录验证回放。
- 测试按修改范围选择；只有行为变更或新证据缺口才触发完整研究矩阵重跑。

旧结果使用其归档代码与配置解释。入口或路径迁移若改变源码指纹，建立显式迁移记录；
不放宽历史复用检查，也不把新代码输出续写进旧实验目录。

## 6. 本次重构后的交付与后续完善

本次交付：三层项目说明、模型基线记录、控制研究协议、分层实验入口、
系统验证与 Demo 入口、历史证据索引，以及迁移验证记录。

后续优先顺序：

1. 核对现有控制证据是否完整覆盖 RQ1/RQ2，仅补齐缺失的配对或数值检查。
2. 在固定基线上扩展策略适用范围，先选择有研究价值的边界工况。
3. 将选定研究策略接入完整系统，完成局部控制回归与系统级验收。
4. 基于验收记录制作完整对接/装配 Demo。
5. 根据新的研究目标，分别立项接口设计、失败恢复、重力/倾斜推广或真实锁紧。

最终研究报告建议按“问题与假设—模型和实验对象—控制方法—受控实验—系统验证—边界”
组织。接口设计历史作为独立章节或附录引用，完整流程放在系统验证与展示部分。
